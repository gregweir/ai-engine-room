# Support

AI Engine Room 0.1.0 is work-in-progress pre-release software. This matrix describes current evidence, not a compatibility promise.

| Area                                    | Status                                                                                                                                                                                                                          |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Other Linux distributions               | Not currently claimed                                                                                                                                                                                                           |
| Other Linux architectures               | Not currently claimed                                                                                                                                                                                                           |
| Windows 11 25H2 build 26200.7462 x64    | Verified public unsigned NSIS preview baseline; exact-artifact install, native launch, graphical/accessibility, passive-behavior, removal, and post-removal acceptance passed                                                        |
| Windows available memory                | Native compilation, current-source unsigned NSIS packaging, and developer package verification passed on the tested Windows baseline; broader Windows environments are not established                                              |

| Windows total memory / CPU architecture | Bounded native compilation, strict Clippy, value, and presentation verification passed on the tested Windows 11 25H2 x64 baseline, including developer-established 225% Text size; broader support is not claimed                   |
| Other Windows versions/architectures    | Not currently claimed                                                                                                                                                                                                           |
| macOS                                   | Not currently claimed                                                                                                                                                                                                           |

Observed inference requires explicit authorization for each run and uses a fixed synthetic prompt/profile. Ollama execution location is undetermined. LM Studio API scope is same-machine loopback, while exact compute placement is not independently verified; an authorized inference may JIT-load the selected model. The result is an observation, not a benchmark. No inference is needed for deterministic checks or packaging acceptance.

llama.cpp is passive-only in Milestone 1O. On the tested Ubuntu 24.04 LTS x86_64 baseline, the developer verified a traditional single-model llama-server using Snap `llama-cpp` label `b9969`, revision `307`, server build commit `76f2798`, fixed numeric loopback `127.0.0.1:8080`, and the validated provider-reported served-model ID `lfm2.5-1.2b`. AI Engine Room represented one served model rather than a catalogue; navigation and one Refresh remained passive; no path, observation, provider data in Report, inference, POST, or model/server management occurred. The integration rejects redirects and path-like identity and does not support inference, router mode, authentication, TLS, custom endpoints, LAN/remote access, service control, or model management. Its API scope is same-machine loopback and compute location is not independently verified. Windows llama.cpp and compatibility with other builds, configurations, or platforms are not claimed.

The Windows provider evidence is limited to the tested Windows 11 25H2 build 26200.7462 x64 baseline and the fixed loopback APIs: Ollama at `127.0.0.1:11434` and LM Studio native REST v1 at `127.0.0.1:1234`. Passive catalogue, loaded-state, and coexistence checks passed without inference or model/service management. Windows inference was not verified. AI Engine Room's Windows available-memory observation has passed native compilation, current-source unsigned NSIS packaging, and developer package verification on Windows 11 25H2 build 26200.7462 x64. The value is the operating system's reported available physical memory and is not claimed to be numerically equivalent to Linux `MemAvailable`. The [Milestone 1Q evidence](docs/release/windows-available-memory-verification.md) does not establish other Windows versions, builds, architectures, or machines; Windows provider functionality or inference; memory-pressure, model-fit, or headroom recommendations; or verified compute placement. Separate Milestone 1U evidence on that tested Windows environment established bounded native compilation, strict Clippy, exact total-memory agreement with an independent Windows query, controlled native-architecture presentation, normal and narrow layouts, keyboard focus, Report exclusion, and developer-established 225% Windows Text-size presentation. Those milestone artifacts did not themselves establish broad Windows compatibility, packaging or release readiness, WCAG conformance, or a general Windows support claim. Historical Milestone 1M package evidence also remains distinct.

Separately, the exact accepted `.deb` and NSIS artifacts from source commit `a5482e9d51657a0cfb4471215a91750c5ba7db95` are publicly available in the [`v0.1.0-preview.1` unsigned prerelease](https://github.com/gregweir/ai-engine-room/releases/tag/v0.1.0-preview.1). This establishes a public prerelease only; it does not establish a stable, production-ready, signed, release-candidate, security-certified, or broadly compatible product. There is no currently claimed support for broad Linux or Windows compatibility, package repositories, automatic updates, signed packages, macOS, authenticated/custom-port/LAN LM Studio access, or broad provider configuration compatibility. For sensitive security reports, use [SECURITY.md](SECURITY.md). For contribution guidance, see [CONTRIBUTING.md](CONTRIBUTING.md).

The tested AppImage bundled WebKitGTK and GStreamer core/link libraries without exposing the host's installed `appsink` plugin to that runtime. The supported Tauri media-framework option would materially broaden bundled plugin and helper contents, so the developer deferred AppImage for separate future packaging research rather than expanding Milestone 1K. This is not a claim that AppImage is permanently unsupported or generally broken.
