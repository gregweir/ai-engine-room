# Milestone 1W-D non-specialist-validation preparation contract

## Status

Developer-approved on 2026-08-31 for one bounded validation-preparation
implementation.

## Purpose

Milestone 1W-D tests whether people outside the project can understand the
public preview's purpose, installation decision, passive workflow, evidence
limits, and optional-inference boundary. This first slice creates a repeatable,
privacy-conscious formative-validation kit. It does not invent participant
evidence or convert preparation into a readiness claim.

## Authorized work

This implementation authorizes only:

- this contract;
- one moderated non-specialist session guide;
- one combined de-identified observation and synthesis template; and
- a roadmap update that distinguishes preparation from completed sessions.

The developer may later use the kit with willing participants on a
facilitator-controlled machine. Each participant must voluntarily agree before
a session begins and may stop at any time. This repository change does not
recruit, contact, schedule, record, or compensate anyone and does not claim that
a session occurred.

## Validation boundaries

- The target is a small formative round of three to five adults who use desktop
  software but did not contribute to AI Engine Room and are not being tested on
  technical expertise. This is not a representative or statistically powered
  sample.
- Use the exact public `v0.1.0-preview.1` documentation and an already installed
  accepted preview on a facilitator-controlled verified platform. Do not ask a
  participant to install unsigned software, accept a warning, weaken a security
  control, or bypass an organizational policy.
- Download and checksum work is a comprehension task only. A participant may
  inspect the official release page and verification instructions without
  opening an installer.
- Use a no-provider state by default. A facilitator-provided supported runtime
  may be observed only when it contains no sensitive identity or data. The
  session does not authorize live inference, provider management, network
  reconfiguration, report sharing, or clipboard transmission.
- Record participant IDs such as `P01`, broad task-relevant experience, and
  paraphrased behavior. Do not record names, contact details, account data,
  precise machine identifiers, exact model identities, exact resource values,
  clipboard contents, photographs, audio, video, or screen recordings.
- A facilitator may stop an unsafe action. Help after a task must be marked as
  help rather than counted as independent completion.
- Results describe only the tested documentation, artifact, platform, session,
  and participants. They do not establish broad usability, accessibility
  conformance, compatibility, security, privacy, production readiness, or a
  recommendation to install unsigned software.

## Critical comprehension boundaries

The session must test, without leading the participant, whether they understand
that:

- `Refresh` reacquires observations and does not run or authorize inference;
- AI Engine Room does not start, stop, install, unload, or configure providers;
- observed inference is optional, disclosed, and authorized one run at a time;
- missing evidence remains unavailable or unknown rather than estimated;
- a matching checksum verifies exact bytes but does not authenticate a
  publisher;
- same-machine loopback scope does not prove compute placement; and
- copying a report is explicit and places text on a clipboard other
  applications may read.

## Explicit exclusions

This slice does not authorize:

- assertions that validation passed or that the product is ready for a wider
  audience;
- changes to the product, UI, providers, inference behavior, dependencies,
  workflow, packages, signing, Store presence, release, or release assets;
- publication of participant notes or raw session evidence;
- unattended testing, analytics, telemetry, remote observation, or data upload;
- recruitment or representational communication to potential participants; or
- remediation based on hypothetical findings.

## Acceptance criteria

The preparation slice is complete only when:

- a facilitator can run the same bounded session with each participant;
- task prompts are neutral and separate observation from later explanation;
- outcomes distinguish independent completion, one neutral prompt, and blocked
  or misunderstood behavior;
- the kit identifies safety-critical findings and prevents preparation from
  being reported as user evidence;
- notes are de-identified by default and exclude sensitive machine or provider
  data;
- synthesis rules preserve limitations and require retesting after material
  remediation; and
- the diff is limited to this contract, the session guide, the observation and
  synthesis template, and the roadmap.

## Subsequent gate

Actual sessions require willing participants and developer-controlled session
execution. Any documentation remediation, product change, or new readiness
statement must be proposed from recorded evidence and separately approved. No
result authorizes signing or another release.
