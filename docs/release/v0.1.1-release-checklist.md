# AI Engine Room 0.1.1 release checklist

This checklist controls the first stable, unsigned release. Historical preview
records remain unchanged.

## Source gate

- [ ] `package.json`, Tauri, and application Cargo versions are exactly 0.1.1.
- [ ] The release source is merged to `main`, clean, and identified by complete
      commit and tree hashes.
- [ ] Ordinary deterministic CI passes on Ubuntu and Windows.
- [ ] Release notes, support, security, and safe-install guidance agree.

## Exact artifacts

- [ ] Build exactly one `.deb` on the verified Ubuntu 24.04 LTS x86_64 host.
- [ ] Build exactly one NSIS installer on the verified Windows 11 x64 host.
- [ ] Record exact filenames, byte sizes, and complete SHA-256 values.
- [ ] Confirm package identity/version/architecture, licence payloads, and the
      expected unsigned state.
- [ ] Create `SHA256SUMS.txt` containing only the two accepted packages.

## Physical acceptance

- [ ] On each verified baseline, install the exact candidate through the normal
      operating-system flow without weakening security controls.
- [ ] Confirm native launch, version 0.1.1 where exposed, core navigation,
      Refresh, Report, Copy, Save, and existing-file no-clobber behavior.
- [ ] Remove the application normally and confirm no application process or
      validation report artifact remains.

## Publication

- [ ] Create tag `v0.1.1` at the accepted source revision.
- [ ] Create a non-prerelease GitHub Release using
      `v0.1.1-release-notes.md` as the reviewed basis.
- [ ] Upload only the accepted `.deb`, NSIS installer, and `SHA256SUMS.txt`.
- [ ] Independently download all three assets and recheck names, byte sizes,
      hashes, unsigned disclosure, support links, and release status.
- [ ] Update the public Tartanleaf publisher page only after the GitHub release
      is verified.

Any mismatch stops publication. Do not replace an asset under the same release
identity; correct the source or version and create a new release.
